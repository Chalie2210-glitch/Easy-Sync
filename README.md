# Easy Sync

Windows에서 오디오 파일을 Wwise로 가져오는 데스크톱 도구입니다.
파일 묶기, 컨테이너 선택, 이벤트 생성, 임포트 위치 확인을 한 화면에서 처리합니다.

[설치 파일 받기](https://github.com/Chalie2210-glitch/Easy-Sync/releases/latest) ·
[변경 기록](CHANGELOG.md) · [개인정보 안내](PRIVACY.md)

이 설명서는 `main` 소스 기준입니다. **자동 이벤트를 실행마다 직접 켜는 변경, Wwise 재연결 개선, 프로젝트별 핀 저장은
아직 v0.1.0 설치 파일에는 포함되어 있지 않습니다.** 배포된 버전의 변경 내용은 릴리스에서 확인하세요.

## 사용 조건

| 항목 | 조건 |
| --- | --- |
| 운영체제 | Windows 10/11 x64 |
| Wwise | WAAPI를 사용할 수 있는 Wwise Authoring과 열린 프로젝트 |
| 연결 | 같은 PC에서 Wwise의 WAAPI 활성화. Easy Sync 기본 연결은 로컬 HTTP 8090, WAMP 8080 |
| 파일 | PC에서 읽을 수 있는 오디오. 추가 대상 확장자는 WAV, AIF, AIFF, FLAC, OGG이며 실제 임포트 가능 여부는 Wwise 버전과 파일 형식에 따름 |
| 저장 권한 | 작업할 Wwise 프로젝트와 Originals 폴더에 쓰기 권한 필요 |
| 인터넷 | GitHub에서 설치 파일을 받거나 업데이트할 때 필요 |

일반적인 작업에서는 Wwise 프로젝트 하나를 열고 사용합니다. 여러 Wwise가 실행 중이라면
Easy Sync 상단에 표시된 연결 프로젝트를 먼저 확인하세요.
기존 Wwise를 닫고 다른 프로젝트를 열면 다시 연결합니다. 프로젝트가 바뀌면 가져온 파일은 유지하고,
이전 목적지·활성 핀·이벤트 체크·스위치 배정을 초기화하므로 새 프로젝트의 위치를 다시 선택하세요.
연결 확인은 기본 15초 간격이며, **Wwise 다시 읽기**를 누르면 바로 확인을 요청할 수 있습니다.
실제 임포트는 Wwise 2025.1.8에서 확인했으며, 이전 버전 Actor-Mixer 계층을 처리하는 코드도 포함합니다.
Wwise 자체와 오디오 파일은 제공하지 않습니다.

## 설치

1. [최신 릴리스](https://github.com/Chalie2210-glitch/Easy-Sync/releases/latest)에서 **Easy-Sync-Setup-x.y.z-x64.exe**를 받습니다.
2. 설치 파일을 실행합니다. Python을 별도로 설치할 필요가 없습니다.
3. 기본 위치는 `%LOCALAPPDATA%\Programs\Easy Sync`입니다. 바로가기·탐색기 메뉴·Wwise 메뉴를 함께 설치할 수 있습니다.
4. Wwise에서 WAAPI를 활성화한 뒤 Easy Sync를 실행합니다.

설치 시 메뉴 등록을 선택하지 않았다면, 나중에 **옵션 → 탐색기 우클릭 메뉴 등록** 또는
**옵션 → Wwise 우클릭 메뉴 등록**으로 추가할 수 있습니다.
기본 Wwise 단축키는 등록하지 않으므로 필요한 키는 Wwise 단축키 관리자에서 지정하세요.

## 기본 작업 순서

### 1. 연결과 오디오 위치 확인

Wwise 프로젝트를 연 뒤 Easy Sync를 실행하고 상단의 프로젝트 이름과 연결 상태를 확인합니다.
왼쪽 오디오 트리에서 파일을 넣을 상위 액터믹서, 폴더 또는 컨테이너를 선택합니다.

화면의 경로는 다음 세 가지를 구분해서 봅니다.

| 경로 | 의미 |
| --- | --- |
| 오디오 위치 | Wwise 안에서 Sound와 컨테이너가 만들어질 위치 |
| 이벤트 위치 | 새 Event 오브젝트가 만들어질 위치 |
| 오리지날 wav 위치 | Wwise 프로젝트가 임포트한 오디오를 보관하는 Originals 하위 폴더 |

Easy Sync에 처음 추가한 외부 파일의 위치는 Originals와 별개입니다.

오디오와 이벤트 탭의 **핀 고정**은 현재 연결된 Wwise 프로젝트별로 즉시 저장됩니다.
프로젝트를 바꾸면 그 프로젝트의 핀 목록을 불러오고, 다시 돌아오거나 Easy Sync를 재실행해도 유지됩니다.
전환 직후에는 **핀 없음 (전체 보기)**에서 시작하므로 사용할 핀을 선택하세요.
프로젝트는 `.wproj` 파일의 전체 경로로 구분합니다. 이름이 같아도 위치가 다르면 별도로 저장하며,
프로젝트 파일을 이동하거나 이름을 바꾼 경우에는 핀을 다시 등록해야 합니다.
이전 버전의 공용 핀은 소속 프로젝트를 알 수 없어 자동으로 적용하지 않습니다.
기존 목록은 설정 파일에 보관되며, 필요한 핀을 각 프로젝트에서 한 번씩 다시 등록하세요.

### 2. 파일 추가

다음 중 편한 방법을 사용합니다.

- 창의 **파일 추가...** 또는 **파일 → 파일 추가...** (`Ctrl+O`).
- 탐색기에서 오디오 파일을 Easy Sync 창으로 드래그.
- 탐색기에서 오디오 파일 또는 폴더 우클릭 → **Easy Sync 로 보내기**.
- 탐색기 우클릭 → **보내기 → Easy Sync**.

Windows 11의 기존 우클릭 메뉴는 **추가 옵션 표시** 안에 있습니다.
폴더를 보내면 하위 폴더의 오디오도 함께 추가됩니다.
**목록 비우기**는 Easy Sync 목록을 비우는 기능이며 Wwise 오브젝트를 삭제하지 않습니다.

### 3. 필요한 파일만 묶기

**자동 묶기**는 기본으로 꺼져 있습니다. 켜면 파일 이름의 끝 번호를 기준으로 묶으며,
묶음의 기본 컨테이너는 **Random**입니다.

예를 들어 `Footstep_01.wav`, `Footstep_02.wav`, `Footstep_03.wav`를 자동으로 묶으면
`Footstep` 묶음에 세 파일이 들어갑니다. 숫자만 보고 묶는 기능이므로 결과 이름과 파일 구성을 확인하세요.
필요한 항목만 선택해 우클릭으로 묶을 수도 있습니다.

기존 위치에 Switch나 Sequence가 있는데 Random으로 가져오려고 하면 타입 충돌을 알립니다.
이 경우 원하는 컨테이너 종류와 목적지를 다시 선택하세요.

### 4. 이벤트 생성 여부 선택

오디오만 추가하거나 기존 파일을 교체할 때는 이벤트 칸을 끈 상태로 작업합니다.
새 이벤트가 필요한 항목은 목록 맨 왼쪽의 **이벤트** 칸을 직접 체크하고 이벤트 위치를 선택합니다.

**자동 이벤트**를 켜면 현재 목록과 이후 추가하는 파일에 이벤트 체크가 적용됩니다.
`main` 소스에서는 이 선택을 저장하지 않으며, 프로그램을 다시 열면 꺼진 상태로 시작합니다.
같은 창에서 작업을 계속하는 동안에는 켠 상태가 유지됩니다.

이벤트 이름에 `Play_`를 자동으로 붙이지 않습니다. 생성되는 이벤트에는 재생을 위한 Play 액션이 들어갑니다.
묶음 이벤트는 해당 컨테이너를, 낱개 이벤트는 해당 Sound를 재생 대상으로 사용합니다.

### 5. 만들어질 위치 확인 후 임포트

**만들어질 위치**에서 오디오·이벤트·Originals 경로를 확인합니다.
확인이 필요한 항목을 해결한 다음 **임포트**를 누르고 완료 결과를 확인합니다.
임포트가 끝나면 Wwise에서도 생성된 오브젝트와 필요한 이벤트를 확인하고 프로젝트를 저장합니다.

## 자주 사용하는 작업

### 새 효과음 추가

1. Wwise의 목적지를 선택하고 오디오를 추가합니다.
2. 여러 변형을 랜덤 재생하려면 자동 묶기 또는 선택 항목 묶기를 사용합니다.
3. **옵션 → 옵션... → 이미 있을 때**를 확인합니다. 기본은 **이미 있으면 그대로 둠**입니다.
4. 새 이벤트가 필요할 때만 이벤트를 체크하고 임포트합니다.

### 수정한 오디오로 교체

1. 수정된 파일을 추가하고 기존 Sound와 **같은 이름·같은 Wwise 위치**가 되도록 맞춥니다.
2. **옵션 → 옵션... → 이미 있을 때 → 이미 있으면 오디오 교체**를 선택합니다.
3. 이벤트 체크를 끄고, 만들어질 경로를 확인한 후 임포트합니다.

이 방식은 기존 Sound 오브젝트를 유지하고 오디오를 교체하므로 기존 이벤트의 대상 참조도 유지됩니다.
이름이나 경로를 바꾸거나 **항상 새로 만듦**을 선택하면 별도 오브젝트가 될 수 있습니다.
새 오브젝트로 만든 경우 기존 이벤트가 새 대상을 자동으로 가리키는 것은 아닙니다.

| 이미 있을 때 | 사용할 상황 |
| --- | --- |
| 이미 있으면 그대로 둠 | 기존 오디오는 유지하고 아직 없는 파일만 추가 |
| 이미 있으면 오디오 교체 | 같은 Sound의 오디오를 새 바운스 파일로 갱신 |
| 항상 새로 만듦 (_01 붙음) | 기존 오브젝트와 별개로 새 항목을 추가 |

### Originals 정리와 보이스

- **스마트 wav**: 옵션에서 선택한 Wwise 계층 종류를 따라 Originals 하위 폴더를 만듭니다.
- **수동**: 임포트할 때 Originals 안의 저장 위치를 직접 고릅니다.
- **보이스로 임포트**: Sound Voice로 가져오며 Wwise 프로젝트의 기본 언어를 사용합니다.
  프로젝트에 설정된 언어와 `Originals/Voices/<언어>` 위치를 확인하세요.
- **경로 추천**: 기본은 꺼져 있습니다. 켜서 받은 추천도 실제 목적지가 맞는지 확인하고 적용합니다.

### 처음 가져온 외부 원본 찾기

Wwise에서 Sound 또는 Audio Source를 우클릭하고
**Easy Sync → 가져온 원본 파일 찾기**를 선택합니다.

임포트 때 기록한 외부 파일의 절대 경로로 탐색기를 엽니다.
파일을 이동·삭제했거나 경로 기록이 없는 이전 임포트라면 찾을 수 없습니다.
이 기능은 다른 위치의 같은 이름 파일을 검색하지 않습니다.
기록은 Wwise Sound Notes에 들어가므로 프로젝트를 공유할 때 원본 경로도 함께 전달될 수 있습니다.

## 업데이트

**도움말 → 업데이트 확인**에서 최신 정식 릴리스를 확인하고 다운로드합니다.
크기와 GitHub SHA-256 값을 검증한 후 설치를 누르면 앱이 종료되고 설치 프로그램이 열립니다.
업데이트를 강제 실행하지 않습니다. 인터넷이 없거나 검증에 실패해도 기존 앱을 사용할 수 있습니다.

새 설치 파일을 직접 실행해도 같은 위치에 갱신됩니다. 버전 간 설치 ID는 유지됩니다.
임포트 중에는 종료·업데이트를 막습니다. 설치 프로그램은 Easy Sync가 종료될 때까지 기다리며 Wwise를 강제 종료하지 않습니다.

- 설정/즐겨찾기: `%APPDATA%\EasySync\settings.json`
- 로그: `%LOCALAPPDATA%\EasySync\Logs`
- 다운로드: `%LOCALAPPDATA%\EasySync\Updates`

설정은 업데이트와 프로그램 제거 후에도 보존됩니다. `main`의 자동 이벤트 체크는 저장 대상에서 제외됩니다.

## 문제가 있을 때

| 증상 | 확인할 내용 |
| --- | --- |
| Wwise에 연결되지 않음 | 프로젝트가 열려 있는지, WAAPI가 켜져 있는지, 다른 Wwise 인스턴스에 연결되지 않았는지 확인 |
| Wwise 응답이 늦거나 임포트가 진행되지 않음 | Wwise에 떠 있는 대화상자를 닫고 연결 상태 확인 |
| 계층이 변경됐는데 화면에 반영되지 않음 | **파일 → Wwise 다시 읽기** (`F5`) |
| 같은 파일을 다시 넣어도 오디오가 바뀌지 않음 | **이미 있으면 그대로 둠** 대신 **이미 있으면 오디오 교체** 선택 |
| 우클릭 메뉴가 보이지 않음 | 옵션에서 메뉴 재등록, Windows 11의 **추가 옵션 표시** 확인 |
| 파일을 많이 선택하면 메뉴가 사라짐 | 폴더 자체 보내기 또는 파일 드래그 사용. 아래 알려진 제한 참고 |

문제를 제보할 때는 Windows/Wwise 버전, 수행한 작업 순서와 오류 메시지를 적어 주세요.
로그나 화면을 첨부하기 전에는 개인 경로와 프로젝트 이름을 가려 주세요.

## 알려진 제한

- 탐색기 정적 메뉴는 최대 100개 선택 모델입니다. 더 많은 파일은 폴더 자체 보내기 또는 드래그 앤 드롭을 사용하세요.
- 일부 실행 중인 탐색기에서 16개 이상 선택 시 메뉴가 사라지는 현상을 확인했습니다. 원인은 확인 중입니다. 폴더 보내기·드래그 앤 드롭을 사용할 수 있습니다.
- 첫 공개 빌드는 코드 서명 인증서가 없습니다.
- 설치된 Wwise의 아이콘을 런타임에 읽으며 해당 아이콘을 재배포하지 않습니다.

## 소스 실행 / 빌드

소스 실행에는 Python 3.12 x64, 설치 파일 생성에는 Inno Setup 6도 필요합니다.
저장소 폴더의 PowerShell에서:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe run_easysync.pyw
.\packaging\build.ps1 -Python .\.venv\Scripts\python.exe
```

결과: `dist/release/Easy-Sync-Setup-x.y.z-x64.exe`, `SHA256SUMS.txt`.
PyInstaller 폴더 배포 방식으로 실행 시마다 임시 폴더에 압축을 풀지 않습니다.
Qt 공유 라이브러리는 `_internal`에 별도로 배치됩니다.

`easysync/version.py` 버전을 올리고 `vX.Y.Z` 태그를 푸시하면 GitHub Actions가
Windows 빌드와 배포 실행 파일의 시작 확인 후 릴리스를 발행합니다.

### 저장소 구성

| 경로 | 내용 |
| --- | --- |
| `easysync/` | 화면, 파일 묶기, Wwise 연결·임포트와 업데이트 소스 |
